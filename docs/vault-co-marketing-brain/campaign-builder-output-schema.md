# Campaign Builder Output Schema

The complete structure of a campaign draft generated by the Vault Co AI Campaign Builder. Every field in this schema is documented below with its purpose and content expectations.

## Root Object: CampaignDraft

| Field | Type | Description |
|---|---|---|
| `id` | string | Unique draft ID (e.g., `plan-1714000000000`) |
| `clientId` | string | Client identifier |
| `clientName` | string | Client display name |
| `campaignName` | string | Descriptive name (e.g., "Free Roof Inspection — Lead Gen — Phoenix") |
| `market` | string | Target market city or DMA |
| `service` | string | Service being promoted |
| `goal` | string | Campaign goal |
| `budget` | string | Monthly ad budget (e.g., "$2,500/mo") |
| `creativeType` | string | Creative format selected |
| `status` | DraftStatus | Draft workflow status |
| `approvalStatus` | DraftStatus | Approval workflow status |
| `createdAt` | string | Creation timestamp |
| `updatedAt` | string | Last update timestamp |
| `createdBy` | string | "AI Agent" for generated drafts |

---

## Section 1 — Meta Campaign Structure (`metaStructure`)

Defines the technical structure of the Meta campaign.

| Field | Description |
|---|---|
| `campaignObjective` | `LEAD_GENERATION`, `CONVERSIONS`, or `AWARENESS` |
| `campaignType` | e.g., "Instant Form (Native Lead Form)" |
| `adSetNames` | Array of 4 ad set names targeting distinct audience segments |
| `audience` | Detailed audience description with demographics, interests, estimated reach |
| `locationTargeting` | Primary city, radius miles, DMA, exclusion zones |
| `placements` | Array of Meta placements (Facebook Feed, Instagram Reels, etc.) |
| `budgetSplit` | Budget allocation across ad sets |
| `optimizationEvent` | e.g., "LEAD (Meta Instant Form Submit)" |

---

## Section 2 — Ad Copy (`adCopy`)

All copy variants for the campaign.

| Field | Description |
|---|---|
| `primaryTexts` | Array of 3 primary text variants (200–400 characters each) |
| `headlines` | Array of 3 headline variants (40 characters max each) |
| `descriptions` | Array of 3 description variants (30 characters max each) |
| `cta` | CTA button text (e.g., "Get My Free Inspection") |

**Copy requirements:**
- Each variant must address a distinct angle (trust, urgency, proof)
- All variants must be compliant — no false claims, no guaranteed outcomes
- Headlines must be specific to the market and service
- CTA must match the offer (not generic "Learn More" for a lead-gen form)

---

## Section 3 — Lead Form (`leadForm`)

The Meta Instant Form or landing page form configuration.

| Field | Description |
|---|---|
| `formName` | Descriptive form name including client and service |
| `introCopy` | 2–3 sentence intro explaining the offer and next step |
| `qualificationQuestions` | Array of 2–4 pre-qualification questions |
| `contactFields` | Fields to collect: name, phone, email, address |
| `consentLanguage` | TCPA-compliant SMS/email consent with STOP opt-out instruction |
| `thankYouCopy` | Confirmation message setting expectations for next contact |

**Lead form requirements:**
- TCPA consent language is mandatory for all SMS follow-up campaigns
- Qualification questions should filter for homeownership and property type at minimum
- Thank-you copy should specify when the lead will be contacted (e.g., "within 5 minutes")

---

## Section 4 — GHL Follow-Up Workflow (`ghlWorkflow`)

The complete GoHighLevel automation sequence.

| Field | Description |
|---|---|
| `tags` | CRM tags to apply on lead creation |
| `pipelineStage` | Initial pipeline stage |
| `immediateSms` | SMS sent within 60 seconds of form submission |
| `immediateEmail` | Object: `{ subject, body }` sent within 60 seconds |
| `internalNotification` | Alert to setter/owner with lead details |
| `setterTask` | Task instructions for the setter including script guidance |
| `aiVoiceTrigger` | AI voice script if no live call within 10 minutes |
| `bookedStopCondition` | Instructions to stop all sequences when appointment is booked |
| `steps` | Numbered array of all workflow steps with timing |

---

## Section 5 — Creative Direction (`creativeDirection`)

Production brief for the creative asset.

| Field | Description |
|---|---|
| `angle` | Creative angle/concept name |
| `hook` | Opening hook line for the ad |
| `shotList` | Array of 6–8 specific shots for video production |
| `textOverlays` | Array of 4 text overlay directions with placement notes |
| `voiceoverScript` | Full 30-second voiceover script with timestamps |
| `recommendedFormat` | Format specs for different placements |
| `recommendedPlacements` | Ordered list of placements, primary first |

---

## Section 6 — Compliance Check (`compliance`)

Risk assessment and flagged items.

| Field | Description |
|---|---|
| `metaRisk` | `LOW`, `MEDIUM`, or `HIGH` with description |
| `smsCompliance` | TCPA compliance notes for the SMS workflow |
| `insuranceRisk` | Insurance claim language risk assessment, or "N/A" |
| `disallowedPhrases` | Specific phrases to avoid in this campaign |
| `approvalWarnings` | Items requiring human review before launch |

---

## Section 7 — Optimization Rules (`optimization`)

Performance thresholds and scaling rules.

| Field | Description |
|---|---|
| `cplThreshold` | Maximum acceptable cost per lead |
| `cpbaThreshold` | Maximum acceptable cost per booked appointment |
| `bookingRateFloor` | Minimum acceptable booking rate (leads to appointments) |
| `creativeFatigueTrigger` | When to rotate creative (e.g., CTR drops 30% week-over-week) |
| `budgetScalingRule` | When and how to increase budget |
| `pauseRule` | Conditions that require pausing the campaign |
| `humanApprovalTriggers` | Actions that require human approval (budget increases, new creative, etc.) |

---

## Draft Status Flow

```
draft → needs_review → approved → ready_for_meta
                    ↘ rejected
                    ↘ changes_requested → (back to draft for revision)
```

| Status | Description |
|---|---|
| `draft` | Generated but not submitted |
| `needs_review` | Submitted for human approval |
| `changes_requested` | Reviewer requested edits |
| `approved` | Human-approved |
| `ready_for_meta` | Approved and ready to publish |
| `rejected` | Rejected, not to be launched |
| `pushed_paused` | Published to Meta in paused state |
| `live` | Active on Meta |

## Safety Rule

**The AI generates drafts and recommendations only.** It cannot publish campaigns, activate ads, increase budgets, send reports, or push GHL workflows without explicit human approval. This rule is enforced in the system prompt, the UI safety banner, and every approval action in the workflow.
